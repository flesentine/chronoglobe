# Security Policy

## Supported version

ChronoGlobe is a static browser game deployed from the `main` branch. Only the current production release is supported with security updates.

| Version | Supported |
| --- | --- |
| Current production release (`1.9.x`) | Yes |
| Earlier releases and historical commits | No |

## Reporting a vulnerability

Please do not publish exploit details, proof-of-concept code, private user information, or other sensitive security material in a public issue.

Use GitHub's **Security** tab and choose **Report a vulnerability** to submit a private report when that option is available.

If private reporting is unavailable, open a public issue containing only a brief request for a private contact channel. Do not include technical details that would make the vulnerability easier to exploit.

A useful private report includes:

- the affected page, file, or feature;
- clear reproduction steps;
- the expected and observed behavior;
- the likely impact;
- relevant browser and operating-system details;
- suggested remediation, when known.

## Response expectations

Reports will be reviewed as availability permits. Valid reports should receive an acknowledgment, an impact assessment, and a remediation plan before public disclosure. Please allow reasonable time for investigation and deployment before sharing details publicly.

## Scope

Security issues may include unsafe script or dependency loading, cross-site scripting, exposure of private data, compromised release workflows, or weaknesses that allow a third party to alter game behavior for other users.

Ordinary game bugs, historical-content corrections, scoring disagreements, and visual defects should be filed as normal issues rather than security reports.
